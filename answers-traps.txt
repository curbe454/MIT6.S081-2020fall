## Which registers contain arguments to functions? For example, which register holds 13 in main's call to printf?

`a0`-`a7`.

For `printf("%d %d\n", f(8)+1, 13);`, `a0` saves the value of the result of the expr `f(8)+1`, `a1` stores the value `13`.

## Where is the call to function f in the assembly code for main? Where is the call to g? (Hint: the compiler may inline functions.)

```asm
000000000000001c <main>:

void main(void) {
  1c:	1141                	addi	sp,sp,-16
  1e:	e406                	sd	ra,8(sp)
  20:	e022                	sd	s0,0(sp)

  printf("%d %d\n", f(8)+1, 13);
  24:	4635                	li	a2,13

  30:	00000097          	auipc	ra,0x0
```

There is no function call to `f(int)` and `g(int)`. It seems that they're evaluated when compiling.

## At what address is the function printf located?

At va `0x628`.

## What value is in the register ra just after the jalr to printf in main?

zero.

## Endian

> Run the following code.
>
> 	unsigned int i = 0x00646c72;
> 	printf("H%x Wo%s", 57616, &i);
>
> What is the output? Here's an ASCII table that maps bytes to characters.
> The output depends on that fact that the RISC-V is little-endian. If the RISC-V were instead big-endian what would you set i to in order to yield the same output? Would you need to change 57616 to a different value?

```shell
python3 -c 'print(f"H{hex(57616)[2:]} Wo{str().join([ chr(n) for n in [0x72, 0x6c, 0x64, 0x00] ])}")'
# or run `./hello` in xv6
```

It prints `He110 World`.

If it's big-endian, the output will be `He110 Wo`. The value `57616` doesn't need to change.
